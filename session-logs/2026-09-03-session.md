## Entry 006 — 2026-09-03

**Prompt:**
> what should we use for fill in?

**No commands run.** Recommended fill-in prompt + economy notes recorded below.

**Key economy finding from Entry 004:** work packets are written **per gap**, but their
evidence is **per script component**. The 4 `StagingCustomers.*` packets all carry the *same*
script source and the *same* `EvidenceSha256`
(`4337f12e...`); both `SalesSummary.*` packets share `e886e450...`. So reading 1 packet per
component instead of 1 per gap cuts 8 packet reads to 4, with zero information loss. Each
packet also repeats ~30 lines of identical "SSIS semantics you must preserve" boilerplate.

**Etl.Core API surface needed for fills** (pin this in the prompt; avoids ~6 file reads):
- `RowContext(long RowNumber, DateTime LoadedAtUtc, string SourceName)`
- `LoadContext(Guid RunId, DateTime StartedAtUtc, string PackageName)`
- `ScriptTaskContext(IUnitOfWork Uow, LoadContext Load, PackageVariables Variables, IServiceProvider Services)`
- `PackageVariables`: `Get<T>(name, fallback)`, `GetRequired<T>`, `TryGet<T>`, `Set`, `Contains`
- `IUnitOfWork`: `Context` (DbContext), `ExecuteSqlAsync(sql, ct)`,
  `ExecuteSqlAsync(sql, object?[] parameters, ct)` using EF `{0}` placeholders,
  `BulkInsertAsync`, `ExecuteSqlWithoutTransactionAsync`
- File paths: `IOptions<FileSourceOptions>.Value["<Name>"].ResolvedPath`

**Build gotcha:** generated `Directory.Build.props` sets `TreatWarningsAsErrors=true` with
`Nullable=enable` — a sloppy fill fails the build on a warning.

**File convention:** one fill file per generated class (not per gap), at
`fills-library\<Package>\<ClassName>.Fills.cs`, with one `// ssisx-fill:` line per seam.
