## 5. Root cause, established over the session

The VS 2022 SSIS extension **ships** SSIS runtime binaries for 140/150/160/170 but does
**not register their COM classes**. Registration normally comes from installing the
Integration Services *product* feature. Consequences before the fix:

* Native pipeline components (Flat File, OLE DB) worked → data flows ran.
* Any **managed task** (Script Task, *and even a plain Execute SQL Task*) failed with
  `0xC0010026 The task has failed to load`.
* Any **managed pipeline component** (Script Component) failed with `0xC0048021`.
* `dtexec` failed with `0x80040154 REGDB_E_CLASSNOTREG`.

Only SQL Server **2016 (130)** was registered (98 CLSIDs), installed by the extension's
"SQL Server Integration Services 2016" 13.3.7030.0 component.

Installing IS 2022 (§2) registered **160** and supplied the managed assemblies.

## 6d. Building Script Tasks / Components WITHOUT the designer

All four script artifacts were generated, compiled and embedded from the command line.
The recipe is in `tools\Wire-ScriptComponent.ps1`, `tools\Wire-ScriptComponent2.ps1`,
`tools\Graft-ScriptTask.ps1`, `tools\Add-AdoNetConnectionManager.ps1`; sources in
`Scripts\Generated\`.

### Script Component contract (both work)

* Compile `BufferWrapper.cs` + `ComponentWrapper.cs` + `main.cs` with `csc.exe` against
  `Microsoft.SqlServer.TxScript` (160 PipelineComponents) plus `PipelineHost`,
  `DTSPipelineWrap`, `DTSRuntimeWrap`, `ManagedDTS` from the GAC at **16.0.0.0**.
* `ScriptMain` must derive from the generated `UserComponent : ScriptComponent` and carry
  `[SSISScriptComponentEntryPoint]`. The host finds it by scanning `GetExportedTypes()`.
* `BufferWrapper` indexes are **ordinal positions in `GetColumnIndexes(inputID)`**: input
  columns first in input-column order, then the synchronous output's added columns.
* `component version="13"`, `contactInfo` ending `;13`.
* `BinaryCode` is `isArray="true"` and persists as
  `<arrayElements arrayElementCount="2"><arrayElement><![CDATA[assemblyName]]>…<![CDATA[base64]]>`
  — a **(name, base64) pair**, because `ScriptComponentHost.GetBinaryCode(string assemblyname)`
  looks it up by name. `arrayElementCount` goes on `arrayElements`, not on `property`.
* `SourceCode` is **(fileName, encoding, content) triplets**. It is not optional —
  without it validation fails with *"The script component includes no code."*
* `UserComponentTypeName` stays `Microsoft.ScriptComponentHost` (it names the host, not
  your class).
* Delete `MetadataChecksum140` — it is computed by the designer over the column metadata
  and cannot be recomputed outside it (`GetMetadataChecksum` is private and needs a live
  host). A stale value fails with *"component metadata is out of sync with the compiled script"*.
* Added output columns need `errorRowDisposition="NotUsed"` / `truncationRowDisposition="NotUsed"`
  — the XML value is `NotUsed`, **not** the COM enum name `RD_NotUsed`.

### Making a hand-grafted Script Component designer-openable *(done 20:18)*

A component grafted by the tools carried only **3** `SourceCode` files — `ComponentWrapper.cs`,
`BufferWrapper.cs`, `main.cs`. That is enough to *run* (the runtime loads `BinaryCode` and
never compiles) but **not enough to open in the designer**: VSTA needs an actual project.
A designer-generated component carries **10** files, in this exact order and encoding:

```
ComponentWrapper.cs [UTF8]          Properties\Settings.Designer.cs [UTF8]
Properties\Resources.resx [UTF8]    <VSTAProjectName>.csproj [UTF8]
main.cs [UTF8]                      Project [UTF16LE]   <- the descriptor
BufferWrapper.cs [UTF8]             Properties\AssemblyInfo.cs [UTF8]
                                    Properties\Settings.settings [UTF8]
                                    Properties\Resources.Designer.cs [UTF8]
```

The missing 7 were templated from the real designer-generated component in
`Package.WithScriptComponent.dtsx.bak`, substituting the reference project name for our
`VSTAProjectName` (`SC_CleanseCustomerRow_gen` / `SC_ComputeCustomerTier_gen` — which must
equal the `BinaryCode` key, since `GetBinaryCode` looks the assembly up by name) and giving
each component its own deterministic `ProjectId` / `ProjectGuid`. `arrayElementCount` went
`9 → 30`. The 3 original files were preserved byte-for-byte and `BinaryCode` was not touched,
so runtime behaviour is unchanged.

`MetadataChecksum140` was deliberately **not** added, even though the reference has one — a
value that does not match the live column metadata fails with *"component metadata is out of
sync with the compiled script"*, and it cannot be recomputed outside the designer.

Script *Tasks* needed nothing: `SCR_ValidateAndLogStart` was grafted from a designer-generated
backup and already had its full 8-item `ProjectItem` set.

Script: `scratchpad\add_vsta_project.py` (idempotent — skips components already at 10 files).

**Microsoft's own object model**, letting its serializer emit the format:

```powershell
$app  = New-Object Microsoft.SqlServer.Dts.Runtime.Application
$pkg  = $app.LoadPackage($path, $null)
$exec = $pkg.Executables.Add('Microsoft.ScriptTask')
$task = $exec.InnerObject
$task.ScriptLanguage = 'Microsoft Visual Basic 2019'   # exact string; also the DEFAULT
$task.ScriptStorage.AssemblyCode = [IO.File]::ReadAllBytes($dll)   # raw PE bytes
$task.ScriptStorage.ScriptFiles[$rel] = New VSTAScriptFile(UTF8, $text)
$app.SaveToXml($path, $pkg, $null)
```

Format is then correct by construction — no reverse-engineering needed.

Tool: **`tools\Add-VbScriptTask.ps1`** (rewritten; idempotent, takes `-After`/`-Before` to
sequence the task, verifies the reload before returning).

#### What the earlier investigation got wrong

| Earlier claim | Reality (measured from API-generated XML) |
|---|---|
| "VB stores ProjectItems base64-encoded" | **False.** VB uses plain CDATA, exactly like C#. |
| "at least one item is parsed as XML" | No such item exists for VB. |
| needs `Project` descriptor like C# | **The opposite** — a VB task has **no `Project` item at all.** C# has 8 items, VB has 7. Carrying the C# descriptor over is the likeliest cause of the old `FormatException`. |

Other facts worth keeping:

* `Language="VisualBasic"` in the XML; the API string is `Microsoft Visual Basic 2019`
  (`VisualBasic` and `Microsoft Visual Basic` both raise
  `UnrecognizedScriptLanguageException`).
* Item layout is `My Project\…` (not `Properties\…`), from Microsoft's own

* An `Application.LoadPackage` → `SaveToXml` round-trip of `Package.dtsx` was verified

## 8. Gotchas — every one of these cost real time

* **`Customers.csv` must be CRLF.** With LF-only endings SSIS warns `0x8020202B`
  *"end of the data file was reached while reading header rows"*, processes **0 rows, and
  still reports Success.** A silent zero-row load = row-delimiter mismatch.
* **`lineageId` is a hierarchical path, not an integer** —
  `Package\DFT\Component.Outputs[Output].Columns[Col]`. Integers give dozens of
  `0xC001001C ... references ID "1", but no object has this ID`.
* **Synchronous transforms do not re-declare pass-through columns** — they keep
  referencing the original declaring component's lineage path.
* **OLE DB Source error outputs must mirror every regular-output column** plus
  `ErrorCode`/`ErrorColumn`. Flat File Source error outputs instead use a single raw-line
  `text` column.
* **Variable `DataType` uses VARTYPE codes**, not `TypeCode`: `8`=String, `3`=Int32,
  `7`=DateTime. `User::BatchStartTime` is deliberately a **String** (`ToString("o")` /
  `DateTime.Parse()`) because DateTime literals are locale-sensitive.
  Project *parameters* use TypeCode (`18`=String) — different scheme, same file.
* **Never change the VSTA-generated `namespace`.** SSIS resolves the entry point at
  `<RootNamespace>.ScriptMain`; moving the class causes `0xC0010026`. That is why
  `PASTE_*.txt` files contain **fragments only**, not whole files.
  *(Earlier in this session I told the user the namespace didn't matter — it does.)*
* **`.dtproj` is XML** deserialized by `XmlSerializer`, not JSON. It must contain a real
  `<SSIS:Project>` manifest inside `<DeploymentModelSpecificContent><Manifest>`; an empty
  `<Manifest />` gives *"'Project' element for Project is missing"*. The manifest `ID`
  must equal the package `DTSID` (`{5349954B-3550-40D5-8B22-11D011ED9AA4}`).
* **SQL scripts must be BOM-free** when piped to `sqlcmd`, else
  *"Incorrect syntax near '﻿'"*. `init-database.ps1` strips the BOM and uses `docker cp`
  rather than stdin.
* **Benign warnings:** *"external columns out of synchronization"* (destination has table
  columns nothing maps to yet — clears once the Script Components are added) and
  *"Could not open global shared memory … performance DLL"* (perf counters only).
* **`SqlPassword` is a plain, non-Sensitive project parameter** so this local demo runs
  without prompts. **Never do this on a real project** — use a Sensitive parameter plus an
  SSIS catalog Environment or Key Vault.
* SSIS tooling does **not** support VS 2026 — use VS 2022.
